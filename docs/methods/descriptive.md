# 敘述統計（Descriptive Statistics）

> 方法代號 `descriptive`｜基準組 `reference.json → descriptive_y`（9）｜溯源 tier **A** / verified
> 最後更新：2026-07-30（階段 A / A6a）｜相關文件：`visualization.md`、`normality.md`（偏度峰度的另一種用法）

---

## 1. 這個方法在回答什麼問題

敘述統計不做推論，它只回答一個問題：**這批數字長什麼樣子？**

四個面向：**在哪裡**（平均、中位數）、**散多開**（標準差、標準誤、全距）、
**歪向哪一邊**（偏度）、**尾巴多厚**（峰度）。

★ 它是所有後續分析的前置：不先看敘述統計就跑 t 檢定，等於在不知道資料長相的情況下下結論。

## 2. 什麼時候該用、什麼時候不該用

**該用**

- 任何分析的第一步
- 論文的「樣本描述」表（APA 7 要求報 $M$、$SD$、$n$）
- 判斷要不要走無母數：偏度／峰度是比常態性檢定更穩健的判讀依據（見 `normality.md` §2）

**不該用**

- ★ **對類別變項算平均。** 本工具的 Config 只列 `continuous` 與 `ordinal`，但**順序尺度的平均本身有爭議**
  （Likert 的「3.7 分」是什麼意思？）——工具不擋，使用者要自己負責
- **拿標準誤當標準差用**：$SE=SD/\sqrt{n}$ 描述的是「平均數的抽樣變異」，不是資料的離散程度

**常見誤用**

1. ★ **把偏度／峰度的絕對值拿去跟別人的報表比，卻沒說是哪一種算法。**
   三種算法在同一批資料上可以差很多——本工具實測 $n=60$：偏度 0.3993~0.4201、
   **峰度 0.3887~0.6564（差 1.7 倍）**（見 §3.3）
2. **報了 $M$ 與 $SD$ 卻沒報 $n$。**
3. ★ **把峰度的 0 當「常態」的證明。** 峰度 = 0 只代表尾巴厚度與常態相近，形狀可以完全不同

## 3. 公式與定義

### 3.1 符號

| 符號 | 意思 |
|---|---|
| $n$ | 有效樣本數（剔除遺漏值與非數值後） |
| $\bar x$、$s$ | 樣本平均、樣本標準差 |
| $z_i=(x_i-\bar x)/s$ | 標準化分數 |

### 3.2 位置與離散（`descriptive.js:28–69`）

$$\bar x=\frac1n\sum x_i,\qquad
s^2=\frac{1}{n-1}\sum(x_i-\bar x)^2,\qquad
SE=\frac{s}{\sqrt n}$$

★ **變異數用 $n-1$ 分母**（`descriptive.js:35`，`ddof` 預設 1），對齊 SPSS／R 的預設。
中位數為排序後取中（偶數取中間兩個的平均，`descriptive.js:56–61`）。

### 3.3 ★ 偏度與峰度：三種算法，本工具採 type 2

**這一節是本頁最重要的部分。** 偏度與峰度各有三種常見算法，差別在**是否做小樣本校正**：

| 算法 | 偏度 | 本工具實測（$n=60$） |
|---|---|---|
| type 1（$g_1$，動差比） | $\dfrac{m_3}{m_2^{3/2}}$ | 0.40950205 |
| ★ **type 2（$G_1$）** | $\dfrac{n}{(n-1)(n-2)}\sum z_i^3$ | ★ **0.42007779** |
| type 3（$b_1$） | $g_1\left(\dfrac{n-1}{n}\right)^{3/2}$ | 0.39930728 |

| 算法 | 峰度（超額） | 本工具實測（$n=60$） |
|---|---|---|
| type 1 | $\dfrac{m_4}{m_2^2}-3$ | 0.50457175 |
| ★ **type 2（$G_2$）** | $\dfrac{n(n+1)}{(n-1)(n-2)(n-3)}\sum z_i^4-\dfrac{3(n-1)^2}{(n-2)(n-3)}$ | ★ **0.65636834** |
| type 3 | — | 0.38872619 |

**本工具採 type 2**（`descriptive.js:72–101`），對齊 **SPSS／SAS 預設**。
★ **峰度的三種算法在這批資料上差 1.7 倍**——引用時不說明算法等於沒說。

★ **有效範圍**：偏度需 $n\ge3$、峰度需 $n\ge4$，否則回 `NaN`（報表印「—」）；
$s=0$ 時兩者皆回 `NaN`（`descriptive.js:77`、`92`）。

### 3.4 ★ 本工具沒有的東西

**四分位數（Q1／Q3／IQR）完全未實作。** R 的 `quantile()` 有**九種 type**，
是教科書級的慣例分歧點——本工具因為沒有這個欄位，反而不存在分歧風險，
但報表也就缺了 IQR 與箱型圖需要的鉸鏈值。
R 預設（type 7）在本資料集的值供未來實作時當基準：**Q1 = 35.79982500、Q3 = 44.65025000、IQR = 8.85042500**（E81）。

## 4. 假設前提與本工具的檢核方式

敘述統計**沒有統計假設**——它只是描述。但有兩個資料前提：

| 前提 | 本工具怎麼處理 |
|---|---|
| 至少等距尺度（平均才有意義） | Config 只列 `continuous` 與 `ordinal`；★ **順序尺度不擋**，責任在使用者 |
| 數值可解析 | ★ **2026-07-30 起剔除非數值**（`compute.js:25`）。修復前一個 `'abc'` 會讓**整欄八個統計量全變 NaN**，見 §8 的 R65 |
| 遺漏值 | 逐欄 listwise（`compute.js:19`），**剔除筆數不回報**（E82） |
| 零變異 | 偏度／峰度回 `NaN` 印「—」，其餘照常。**不警告**（E83） |

### R65（L2）非數值列讓整欄統計量全變 NaN

**發現**（實跑）：`runDescriptive` 缺少 `.filter(Number.isFinite)`，而 `normality/compute.js` 有。
餵入 `[1, 2, 'abc', 4, 5]`：`Number('abc') = NaN` ⇒
**`mean`／`sd`／`se`／`min`／`max`／`median`／`skew`／`kurt` 八欄全部變 NaN**，
報表印 **n = 5 但其餘八欄全是「—」**，且不說明原因。

★ **這是紅隊第 3 條（同一個判斷有沒有兩套實作）的變體**：同一件事在兩支模組有兩套處理，
其中一支明顯是漏了。

**處置（L2，當場修）**：`compute.js:25` 補上 `.filter(Number.isFinite)`，與 `normality` 對齊；
＋2 條行為測試（含「全數值資料的結果不得被這條過濾改動」的回歸鎖）。
★ **既有 fixture 零影響**（`descriptive_y` 的 `y` 全為數值）。
