# 調節式中介（Moderated mediation／條件間接效果）

> 方法代號 `pls_modmed`｜基準組 `reference.json → pls_modmed`（12 欄）｜溯源 tier **B** / verified
> 最後更新：2026-07-26（階段 A / A2）

---

## 1. 這個方法在回答什麼問題

中介問「X 經由 M 影響 Y」。調節式中介再加一層：**這條經由 M 的路徑，強度會不會隨 W 而變？**

典型情境：「數位工具導入 → 業務流程改造 → 服務效能」這條機制，在**組織支持度高**的機關比較有效。

回報的量是**條件間接效果**：在 W 的不同水準上，間接效果各是多少。

## 2. 什麼時候該用、什麼時候不該用

**該用**：理論上主張某條中介機制的強度取決於第三個變數。

**不該用／要小心**

- **中介本身的因果基礎不穩時**（橫斷面資料），再加一層調節只會讓宣稱更強、證據不變
- **樣本不大**：條件間接效果是三個係數的組合，抽樣變異疊加
- **兩條路徑都被調節時**：條件間接效果對 W 是**二次的**，沒有單一斜率可報（§3.4）

**常見誤用（三條）**

1. **把斜率當成「index of moderated mediation」直接引用。** 那個名稱與其檢定程序出自
   Hayes (2015)，**本專案未取得原文**，因此工具以描述性名稱回報，並在三處標註。詳見 §3.5。
2. **只報 w = 0 的間接效果。** 那就退化成一般中介了，調節的資訊在三個水準的差異裡。
3. **忽略調節變數的主效果。** a 方程必須含 W 的主效果，否則交互係數無法解釋。
   本工具**自動補**（實測：`autoAddedPaths = [{C→F2}]`）。

## 3. 公式與定義

### 3.1 條件 a 路徑與條件 b 路徑

$$a(w)=a_1+a_3w,\qquad b(w)=b_1+b_3w$$

| 符號 | 意義 | 來源 |
|---|---|---|
| $a_1$ | $X\to M$ 的係數 | 路徑表 |
| $a_3$ | $X\times W\to M$ 的**未標準化**交互係數 | 同 two-stage 慣例 |
| $b_1$ | $M\to Y$ 的係數 | 路徑表 |
| $b_3$ | $M\times W\to Y$ 的交互係數（b 路徑被調節時） | 同上 |

→ `src/lib/stats/pls.js:2150–2153–2132`（$a_1$／$b_1$／$a_3$／$b_3$ 的擷取）

### 3.2 條件間接效果

$$\text{indirect}(w)=a(w)\cdot b(w)=(a_1+a_3w)(b_1+b_3w),\qquad w\in\{-1,0,+1\}$$

→ `pls.js:2154–2158–2137`

構念分數已標準化，故 $w=\pm1$ 即 $\mp1$ SD（Aiken & West 1991，與本工具既有的簡單斜率同一組取值）。

### 3.3 斜率（恰一條路徑被調節時）

$$\frac{\mathrm{d}\,\text{indirect}(w)}{\mathrm{d}w}=\begin{cases}a_3b_1 & \text{a 路徑被調節}\\ a_1b_3 & \text{b 路徑被調節}\end{cases}$$

→ `pls.js:2174`

### 3.4 ★ 兩條路徑都被調節時回 `null`

此時 $\text{indirect}(w)=(a_1+a_3w)(b_1+b_3w)$ 對 $w$ 是**二次的**，沒有單一斜率。
本工具的 `slopeOverW` 回 **`null`**、`bothModerated` 標 `true`，
**不硬給一個數**。三個水準的條件間接效果照常回報。

→ `pls.js:2174–2184`

### 3.5 ★ 命名的誠實標註

§3.3 的斜率在文獻上稱為 **index of moderated mediation**，出處為
Hayes (2015), *Multivariate Behavioral Research*, 50(1), 1–22。

**本專案未取得該原文**，因此：

- 工具以**描述性名稱** `slopeOverW` 回報這個量
- 在 **UI／敘述句／provenance 三處**標註「文獻上稱為 index of moderated mediation，標籤待原文核定」
- **未實作該文的檢定程序**（Hayes 對這個 index 有專屬的推論建議）

→ 說明見 `pls.js:2093–2098–2084` 的 JSDoc

### 3.6 範圍限制（程式碼明示）

| 限制 | 理由 | 位置 |
|---|---|---|
| 只處理**兩步鏈** $X\to M\to Y$ | 更長的鏈有多個可被調節的節點，條件效果的定義會分歧 | `pls.js:2135–2146–2121` |
| 交互項須為 **two-stage** 且**恰兩個相異因子** | product-indicator／orthogonal 的係數尺度與簡單斜率慣例不同，混用會造成口徑不一致 | `pls.js:2120–2122–2101` |
| 調節變數不得是 $M$ 或 $Y$ 本身 | W 同時是鏈上節點時解讀退化，屬使用者建模問題 | `pls.js:2147–2149–2128` |

★ 第三條的處理方式是**直接略過不報**——「不給一個看起來合理但講不清的數」（程式碼註解原話）。

### 3.7 bootstrap 推論

條件間接效果與斜率**都是路徑係數的函數**，所以用**同一批 `pathDraws`** 逐次推導，
CI 型別（percentile／BCa）與符號校正沿用主設定，不另立一套。

→ `pls.js:2699–2722–2679`（詳見 `pls-bootstrap.md` §3.6）

## 4. 假設前提與本工具的檢核方式

| 前提 | 本工具怎麼檢核 | 違反時的行為 | 位置 |
|---|---|---|---|
| 存在兩步鏈且至少一條路徑被調節 | 逐對枚舉 | 不符即不輸出（`moderatedMediation` 為 `null`） | `pls.js:2135–2146–2125` |
| 交互項為 two-stage 且恰兩個相異因子 | 篩選 | 不符即不納入 | `pls.js:2120–2122–2101` |
| 調節變數不在鏈上 | 檢查 | **略過該組**，不報 | `pls.js:2147–2149–2128` |
| W 的主效果在 a 方程中 | 不存在就**自動補** | 記入 `meta.autoAddedPaths`（實測 `[{C→F2}]`） | `pls.js:1360–1374` |
| 兩條都被調節 | 檢查 | `slopeOverW` 回 `null`＋`bothModerated: true` | `pls.js:2174–2184` |
| **樣本量是否足夠** | ✗ **不檢核** | 僅一般的 $n<30$ 警告 | `pls.js:2267` |
| **中介的因果基礎** | ✗ **無法檢核** | 無提示 | — |

## 6. 對照與驗證狀態

**基準組**：`reference.json → pls_modmed`（12 欄）

**tier / status**：tier **B** / **verified**

### 三層疊加的驗證策略

本組沒有可執行的第三方（SmartPLS 4 授權過期；seminr 無條件間接效果輸出；
R `processR`／PROCESS 是 OLS 版且需本機 R）。因此策略是
**「把最容易出錯的部分交給第三方，把不會出錯的部分用代數鎖死」**：

| 層 | 內容 |
|---|---|
| 1 | **第三方（重生時 assert，容差 1e−10）**：第二階段兩條方程 $M\sim X+W+z(X\cdot W)$ 與 $Y\sim M+X$ 的全部係數與 $R^2$，由 **statsmodels OLS** 獨立重算並逐值 assert。★ 這道攔的正是最容易錯的地方——**哪些變項進哪條方程**（a 方程漏放 W 主效果、b 方程誤放交互項）與係數擷取位置 |
| 2 | **第一階段有既有第三方錨**：第一階段＝主效果模型的 LV 分數，與 `pls_mod_twostage` 同一條程式路徑，該組第一階段已對 plspm assert <1e−6 |
| 3 | **合成層以代數斷言鎖死**（`tests/pls.test.js`）：$w=0$ 的條件間接效果必須等於一般中介的 $a_1b_1$；恰一條被調節時相鄰兩點的差必須等於 `slopeOverW`；兩條都被調節時 `slopeOverW` 必須為 `null` |

**新增（2026-07-26）**：本文件的獨立重寫，12 欄比對**最大絕對差 4.4e−16**。

### ★ 尚未驗證的部分

1. **★ Hayes (2015) 原文未取得**——`slopeOverW` 的**名稱**與**檢定程序**都待核定（§3.5）。
   數值不受影響（合成層有代數斷言、迴歸層對 statsmodels assert）。
2. **沒有任何第三方對照「條件間接效果」這個量本身**。第三方對的是它的**輸入**（兩條迴歸方程）。
3. ~~範圍限制未在 UI 說明~~ **已於 2026-07-26 補上警告**（§8 R22）。
   **仍未做的**：警告只在「存在中介鏈」時觸發；若模型連中介鏈都沒有（例如只有 X→M），
   使用者同樣看不到條件間接效果，而那是**規格本來就不成立**，工具不另行說明。
4. **同一個交互項會產生兩筆條件間接效果**（§8 R23），數值正確但可能造成困惑。
5. **樣本量對條件間接效果穩定性的影響未提示**。

### R22（L2，已修）不符範圍限制時靜默無輸出

§3.6 的三條限制被觸發時，`moderatedMediation` 直接為 `null`——
**UI 不顯示條件間接效果表，也沒有任何訊息說明為什麼**。

使用者宣告了 `X→M`、`X×W→M`、`M→Y`，但交互項用的是 product-indicator，
或鏈長超過兩步時，會以為「工具不支援這個功能」而不是「你的規格不符合條件」。

**處置（Kevin 2026-07-26 核定，已執行）**：偵測到「模型含交互項、存在中介鏈，
但 `moderatedMediation` 為 `null`」時，於警告區說明原因，並依情形分兩種訊息：

| 情形 | 訊息重點 |
|---|---|
| 沒有任何可用的交互項（非 two-stage，或非恰兩個相異因子） | **指名實際使用的估計法**，並說明「其他估計法的係數尺度與簡單斜率慣例不同，混用會造成口徑不一致」 |
| 有可用交互項但仍無輸出 | 列出三個可能原因：沒有路徑被調節／鏈長超過兩步／調節變數本身在鏈上 |

實測（product-indicator 交互項＋中介鏈）：

```
模型含交互項與中介鏈，但未產生條件間接效果（調節式中介）：交互項的估計法為「product-indicator」。
條件間接效果目前只支援 two-stage 且恰兩個相異因子的交互項——其他估計法的係數尺度與簡單斜率
慣例不同，混用會造成口徑不一致，故不輸出
```

→ `pls.js:2281–2300`。新增 2 條行為測試：非 two-stage 時警告並指名估計法；
**正常的 two-stage 調節式中介不得誤觸發**。

### R23（L1，已記錄）同一個交互項會產生兩筆條件間接效果

**實測**（模型：`F1→F2`、`F1×C→F2`、`F2→Y`、`F1→Y`）：

```
modmed: [{ x: F1, m: F2, y: Y, wA: C,  slope: 0.03242 },
         { x: C,  m: F2, y: Y, wA: F1, slope: 0.03242 }]
```

第二筆把**調節變數 C 當成自變數、F1 當成調節變數**。這在數學上成立
（交互項對兩個因子是對稱的，$a_3b_1$ 相同），但在理論敘事上通常只有第一筆是研究者要的。

**這不是錯誤**——條件間接效果的定義確實對稱，第二筆也是有效的量。
但兩筆數值相同會讓使用者困惑「為什麼報兩次」。

**處置**：本次僅書面記錄（本節與第 6 節第 4 點）。
要區分「哪一個因子是理論上的自變數」需要使用者宣告，屬功能擴充，不在階段 A 範圍。分級 **L1**。
