# 重要性－績效地圖分析 IPMA（Importance–Performance Map Analysis）

> 方法代號 `pls_ipma`｜基準組 `reference.json → pls_ipma`（10 欄）｜溯源 tier **B** / verified
> 最後更新：2026-07-29（階段 A / A3b）

---

## 1. 這個方法在回答什麼問題

路徑係數告訴你「哪個構念影響大」，但實務上還缺一半的資訊：**這個構念現在表現得好不好**。

- 影響大、表現差 → **最該投資源改善**
- 影響大、表現好 → 維持，別搞砸
- 影響小、表現差 → 先別急
- 影響小、表現好 → 別再加碼

IPMA 把這兩件事畫成一張圖：橫軸 **importance**（對目標構念的**非標準化總效果**）、
縱軸 **performance**（構念分數重標定到 0–100 後的平均）。右下象限（重要但表現差）是優先改善區。

★ **為什麼要用非標準化效果**：標準化 $\beta$ 的意思是「前置構念上升一個標準差、目標上升幾個標準差」，
但實務上沒有人以標準差為單位做決策。非標準化總效果的意思是
「**前置構念的 0–100 分數每增加 1 分，目標構念的 0–100 分數平均增加幾分**」——
這是可以直接拿去講的話。

## 2. 什麼時候該用、什麼時候不該用

**該用**

- 研究要給出**實務建議**（哪個構念該優先改善）
- 量表題目**方向一致、量尺相同**（見第 4 節的硬前提）

**不該用**

- 含調節項或高階構念的模型：**直接擋**（`w4-model-not-supported`，`pls.js:3461–3462`）
- 目標構念是外生的：**直接擋**（`ipma-bad-target`）——沒有前置就沒有 importance
- 同一構念內的指標**量尺不同**：0–100 重標定的前提就不成立（官方 cIPMA 教程列為未滿足假設）。
  本工具偵測到全距相差 ≥ 3 倍時**警告**（不擋）
- 有反向題但沒事先反向計分：0–100 分數會反過來，performance 完全錯，**工具無法偵測**

**常見誤用**

1. **把 importance 拿去和結構模型表的標準化 $\beta$ 比大小**。兩者不同尺度，
   數值大小沒有可比性。本工具自 2026-07-29 起把非標準化路徑另列一張表，並在註記寫明這件事
2. **跨樣本比較 performance**。預設用**觀察 min/max** 重標定，
   兩個樣本的極值不同、分母就不同——**跨樣本不可比**。要跨樣本比較必須改用量表理論界線（§3.2）
3. **只看 performance 低就改善**。低 performance 若 importance 也低，改善它對目標沒幫助
4. **以為 importance 是「相關」**。它是**總效果**（直接＋所有間接路徑），
   有中介時會與直接路徑差很多

## 3. 公式與定義

### 3.1 符號表

| 符號 | 意義 |
|---|---|
| $x_{ic}$ | 指標 $c$ 的原始值 |
| $x'_{ic}$ | 重標定到 0–100 的值 |
| $w_{jh}$ | PLS 估出的**標準化**外部權重 |
| $\sigma_c$ | 指標 $c$ 的樣本標準差（ddof = 1） |
| $\tilde w_{jh}$ | 正規化後的非標準化權重（$\sum_h \tilde w_{jh}=1$） |
| $s_{ij}$ | 構念 $j$ 的 0–100 分數 |
| $b^{u}_{jq}$ | 0–100 尺度上的非標準化路徑係數 |

### 3.2 指標重標定到 0–100

$$x'_{ic}=\frac{x_{ic}-\text{lo}_c}{\text{hi}_c-\text{lo}_c}\times 100$$

→ `pls.js:3503–3519`

界線 $(\text{lo}_c,\text{hi}_c)$ 有兩種口徑：

| 口徑 | 界線 | 何時用 |
|---|---|---|
| **觀察 min/max**（本工具**預設**） | 該指標在樣本中的最小／最大值 | 保留本工具原行為與既有 fixture |
| **量表理論界線**（`scaleMin`／`scaleMax`） | 量表本身的理論端點（如 1–7） | **SmartPLS 與 Ringle & Sarstedt (2016) 的口徑**；跨樣本可比 |

→ 口徑判定 `pls.js:3490–3498`；設定入口在 W5 面板（`Config.jsx:905`、`915`）

★ ★ **換界線會同時改變 performance 與 importance，不是只改 performance。**
這一點在 2026-07-25 之前的三處說明是寫錯的，寫成測試斷言後當場紅燈才發現。
理由：觀察界線是「**每個指標各用自己的全距**」縮放，理論界線是「**全部共用同一個分母**」，
兩者產生的合成分數不是同一條線性變換；importance 是這組分數尺度上的非標準化效果，
分數尺度變了係數就跟著變。**兩種界線得到的是兩張不同的 IPMA 圖，不可混著解讀。**

理論界線下若有觀察值超出界線，0–100 分數會落在 0–100 之外——本工具**警告並回報幾個指標超界**
（`pls.js:3509–3513`）。

### 3.3 非標準化權重與構念分數

標準化權重除以指標標準差還原成非標準化，再正規化使總和為 1：

$$w^{u}_{jh}=\frac{w_{jh}}{\sigma_{B_j(h)}},\qquad
\tilde w_{jh}=\frac{w^{u}_{jh}}{\sum_g w^{u}_{jg}},\qquad
s_{ij}=\sum_{h\in B_j}\tilde w_{jh}\,x'_{i,B_j(h)}$$

→ `pls.js:3552–3567`（正規化 `3558`）

★ **$\sum_h\tilde w_{jh}=1$ 是關鍵**：這保證構念分數與指標一樣落在 0–100，
performance 才能解讀成「這個構念平均得幾分」。
（cSEM 文件把這個條件寫成 "length of 1"，措辭不精確——實際是**和**為 1，不是長度為 1。
2026-07-13 逐式核對時確認。）

$\sum_g w^u_{jg}\approx0$ 時無法正規化，回 `ipma-degenerate`（`pls.js:3554–3557`）。
出現負的 $\tilde w$ 時**警告**（Ringle & Sarstedt 2016 的已知限制，`pls.js:3563`）。

### 3.4 非標準化路徑與 importance

對每個內生構念，在 **0–100 分數**上做 OLS（含截距）：

$$s_{\cdot j}=a_j+\sum_{q\in P_j}b^{u}_{jq}\,s_{\cdot q}+\varepsilon$$

→ `pls.js:3572–3580`

**importance ＝ 對目標構念 $T$ 的非標準化總效果**，依拓撲逆序遞迴累加所有路徑：

$$\text{TE}_{T}=1,\qquad \text{TE}_{j}=\sum_{s\,\in\,\text{succ}(j)} b^{u}_{s j}\cdot \text{TE}_{s}$$

→ `pls.js:3582–3596`

**指標層 importance** 依權重分攤：$\text{TE}_j\cdot\tilde w_{jh}$。→ `pls.js:3605–3610`

### 3.5 performance

$$\text{perf}_j=\frac{1}{n}\sum_i s_{ij}\quad(\text{構念}),\qquad
\text{perf}_c=\frac{1}{n}\sum_i x'_{ic}\quad(\text{指標})$$

→ `pls.js:3602`（構念）、`3609`（指標）、`3615`（目標構念的 performance）

### 3.6 判讀

| 象限 | importance | performance | 建議 |
|---|---|---|---|
| 右下 | 高 | 低 | **優先改善** |
| 右上 | 高 | 高 | 維持 |
| 左下 | 低 | 低 | 暫緩 |
| 左上 | 低 | 高 | 不必加碼 |

象限的分界線用的是**本樣本的平均值**（`Result.jsx` 的 `xMean`／`yMean`），
不是任何絕對門檻——**這是相對判讀，不是絕對標準**。

## 4. 假設前提與本工具的檢核方式

| 前提 | 本工具怎麼檢核 | 違反時的行為 | 位置 |
|---|---|---|---|
| 不含調節／高階構念 | `rejectW4` | **硬擋** `w4-model-not-supported` | `pls.js:3461–3462` |
| 目標為內生構念 | 檢查 `spec.pred` | **硬擋** `ipma-bad-target`，指名目標 | `pls.js:3472–3474` |
| 指標有變異 | 標準化時檢查 | **硬擋** `zero-variance`，**指名指標** | `pls.js:3476–3478` |
| 指標可重標定（$\text{hi}>\text{lo}$） | 逐指標 | **硬擋** `ipma-degenerate`，指名指標 | `pls.js:3511` |
| 權重總和非零 | 逐構念 | **硬擋** `ipma-degenerate`，指名構念 | `pls.js:3554–3557` |
| 理論界線設定合法 | `scaleMax > scaleMin` 且皆為數字 | **硬擋** `ipma-bad-scale` | `pls.js:3493–3498` |
| 觀察值落在理論界線內 | 逐指標比對 | **警告**（不擋），回報超界指標數 | `pls.js:3511–3513` |
| **塊內指標同量尺** | 觀察全距比值 ≥ 3 | **警告**（不擋），列出各指標的觀察範圍並建議改用理論界線 | `pls.js:3526–3547` |
| 權重非負 | 逐構念 | **警告**（不擋） | `pls.js:3563` |
| 缺失值 | 沿用模型設定（casewise／pairwise／mean） | 依設定處理 | `pls.js:3466` |

★ **塊內量尺警告的門檻是 3，這是校準過的**：門檻取 1.5 時，連續型指標的純抽樣變異就會誤報
（示範資料的 C 塊三個同尺度指標比值即為 1.53）；真正的量尺混用（如 1–7 混 0–100）比值在 15 倍以上。
取 3 可以分開兩者。**代價是 1–5 混 1–7（比值 1.5）抓不到**——這種情況只能靠使用者自行確認。
這是**啟發式 UI 警告，不是統計量**。

★ **反向題沒有任何檢核**。第 2 節列為誤用，但工具偵測不到——見第 6 節。

### ★ 一個已知的口徑灰區（重要）

**塊內指標量尺不一時，「先縮 0–100 再解權重」與「先解權重再套 0–100」會分岔。**
示範資料的 C 塊就是這種情況：兩種順序得到 `perf_C` = **54.54 vs 55.97**。

- 官方 cIPMA 教程（Sarstedt et al. 2024）把這個情境列為**未滿足假設**（塊內應同量尺）
- SmartPLS 4 授權已過期，**無法對照**
- 本工具採「先縮 0–100 再解權重」（即 §3.2 → §3.3 的順序）

⇒ 這是一個**未被權威核定的分岔**，而它只在「前提本來就沒滿足」時才出現。
本工具的處置是：採一個口徑、書面記錄分岔、並在偵測到塊內量尺差異時警告使用者（第 4 節）。

**已對照過的第三方**：cSEM 0.6.1（R，原始碼＋數值）、numpy（沙盒）。
**沒有對照過**：SmartPLS 4（授權過期）、seminr（無 IPMA）。

### ★ 尚未驗證的部分

1. **Ringle & Sarstedt (2016) 原文未取得。** 全部程序來自 cSEM 原始碼與官方文件。
   §3.4 的「總效果」是否該含所有間接路徑、§3.2 的界線該用哪一種——**原文未核定**。
2. **量尺灰區（上）未被權威解決**，且只在前提未滿足時出現。
3. **預設用觀察 min/max，與 SmartPLS 的口徑不同。** 本工具保留觀察界線為預設是為了不變動既有 fixture，
   但這意味著**預設設定下的 performance 跨樣本不可比**，而使用者不一定會去勾理論界線。
   註記有寫，但**預設值本身就是一個口徑選擇**。
4. **反向題完全不檢核**（第 4 節末）。IPMA 對反向題毫無防禦，而 0–100 分數會整個反過來，
   performance 錯得很徹底卻沒有任何跡象。這是本方法**最容易靜默出錯**的地方。
5. **象限分界用樣本平均**（§3.6），不是絕對門檻——這件事**只在本文件寫了**，UI 註記未說明。
6. **邊界條件未測**：`ipma-degenerate` 的兩條路徑（無法重標定、權重總和為零）、
   `ipma-bad-scale`、超界警告——**皆無測試覆蓋**。
7. **`scores100` 不是報表欄位**：它是 cIPMA 的 NCA 輸入（`pls.js:3621`），
   屬中介產物而非孤兒欄位；`pls.test.js` 有範圍測試。
